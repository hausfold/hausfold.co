```sh
curl -fsSL https://hausfold.co/haus.sh | bash
```

That installs Nix if you don't have it, asks a few questions (which desktop
among them), and writes your config. It does **not** change your Mac: it writes
files, prints the one command that activates them, and offers to run that for
you, so you can stop in between and read what it wrote.

Piped or not, it reaches your terminal and interviews you. Where nobody is
watching (CI, a container, output captured to a file) it takes the defaults and
never offers to switch.

## If you already know which desktop you want

```sh
curl -fsSL https://hausfold.co/hacker.sh    | bash   # the full desktop
curl -fsSL https://hausfold.co/everyday.sh  | bash   # for someone who doesn't write code
curl -fsSL https://hausfold.co/minimal.sh   | bash   # just the themed shell
```

Same script: the URL sets the desktop and skips that question. `haus.sh` is the
one that asks. For the flag instead, give `bash` a `-s --`:

```sh
curl -fsSL https://hausfold.co/haus.sh | bash -s -- --desktop=minimal
```

Every desktop is a set of values for the same options, so anything one chose
your own file overrides in a line. Changing your mind is that line, not a
reinstall.

## Before you start

- A **Mac on Apple Silicon**, running a recent macOS. Intel isn't supported.
- **Xcode Command Line Tools.** The installer prompts for them if they're
  missing, then asks you to re-run.
- **10–15 minutes** and a few GB of download for the first build.

You don't need Nix first: the bootstrap installs [Determinate
Nix](https://docs.determinate.systems/), and if you already run stock Nix it
stops and explains rather than touching your install.

## Read it first, if you like

The URL proxies
[`bootstrap.sh`](https://github.com/hausfold/haus/blob/main/bootstrap.sh) from
the public repo, and it's boring on purpose.

```sh
curl -fsSL https://hausfold.co/haus.sh | less

# or pin an exact release and diff it against GitHub
curl -fsSL 'https://hausfold.co/haus.sh?ref=v2026.07.19' | less
```

A desktop's URL serves that file with two lines added at the top naming the
desktop, so `haus.sh` is the one to diff. You get the latest release by default,
tags are dated, and a **release tag is the only thing `?ref=` accepts**:
anything else is refused rather than fetched, so a link carrying someone else's
commit can't serve you a script off this domain.

## What it does

It takes a Time Machine local snapshot as a coarse rewind point (non-fatal if
Time Machine is off), asks its questions, shows a read-only report of what would
change, then writes `~/.config/nix/` (a small flake importing haus, plus a host
file of your answers) and commits it to git. **No app you installed is ever
removed.**

The questions: your git name and email, a desktop (hacker / everyday / minimal /
custom), an accent colour, a wallpaper, and an editor. haus installs the one you
name, Zed, VS Code, Cursor, helix, neovim, vim or nano (the three apps as casks,
adopting a copy already on your Mac rather than laying down a second one), or
"other" for a command of your own that haus points at and does not install. Then
whether to keep your current Dock, keyboard and Finder settings, and whether to
adopt the Homebrew casks you already have.

<Callout type="warn" title="Dotfiles that would stop the first switch">
The report names any file that would **stop** the switch rather than be backed
up: a dotfile that is a *symlink* (a dotfiles repo, `stow`, `chezmoi`), or one
whose `<file>.backup` name is taken. Home Manager refuses links on purpose,
because silently deleting a link into your dotfiles repo is the worse failure.
Clear each one it lists, or tell haus to skip that file
(`home.file.".profile".enable = false;`), before the build.
</Callout>

Nothing is active yet. The last thing it asks, wherever there's a terminal to
ask on, is whether to change that: say yes and it runs the two commands below,
then `haus doctor`. Unattended it stops here and prints them.

## Build and switch

```sh
cd ~/.config/nix
nix build .#darwinConfigurations.$(scutil --get LocalHostName).system \
  && sudo ./result/sw/bin/darwin-rebuild switch --flake .
```

The first run is slow; it's downloading the world. When it lands, everything
arrives at once: apps install, the bar and tiling start, your terminal is
themed, `haus` joins your `PATH`. After that it's `haus rebuild`.

## If you regret it

| To undo | Use |
|---|---|
| The macOS settings | the snapshot from step 1 |
| Everything haus did | `haus rollback` (atomic, previous generation) |
| Apps | yours. haus never uninstalls one you added |
| All of it | [Leaving](/docs/haus/leaving), every exit in turn, smallest first |

## Unattended installs

Every question has an environment variable, so the whole thing can run without a
prompt:

```sh
HAUS_NONINTERACTIVE=1 \
HAUS_GIT_NAME="Ada Lovelace" \
HAUS_GIT_EMAIL="ada@example.com" \
HAUS_ACCENT="mauve" \
bash -c "$(curl -fsSL https://hausfold.co/haus.sh)"
```

| Variable | Effect |
|---|---|
| `HAUS_NONINTERACTIVE=1` | Take the defaults, Determinate's own confirmation included, so a run with no terminal at all (ssh, CI, a provisioning wrapper) gets through |
| `HAUS_DRY_RUN=1` | Print the config it would write, write nothing; with `--defaults`, silently |
| `HAUS_DESKTOP` | `hacker`, `everyday`, `minimal` or `blank`, or `--desktop=<name>` on the command line. Skips that question even interactively, which is what a desktop's URL does |
| `HAUS_ROOMS` | Rooms to turn on one by one, instead of a desktop's selection |
| `HAUS_GIT_NAME` / `HAUS_GIT_EMAIL` | Your git identity, which the host file records |
| `HAUS_ACCENT` / `HAUS_WALLPAPER` / `HAUS_EDITOR` | The look, and the editor (`zed`, `vscode`, `cursor`, `helix`, `neovim`, `vim`, `nano`) |
| `HAUS_GUI_EDITOR` | Point `$EDITOR` at a command haus does not install (`"subl -w"`); the editor above still installs as fallback |
| `HAUS_KEEP` | macOS settings to leave alone (`dock,keyboard,finder`) |
| `HAUS_DIR` | Scaffold somewhere other than `~/.config/nix` |
| `HAUS_FROM` | Restore an existing config instead of scaffolding |
| `HAUS_PRESET=full` | The pre-desktops spelling for `hacker`, still honoured |

Reach for these if you hand the install to a coding agent: the questions are a
terminal UI, and a tool driving one blind is how someone else's git identity
ends up in your config. An agent can do everything up to the build. The two
`sudo` steps are yours.
