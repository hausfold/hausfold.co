```sh
# scaffold your config; it asks which desktop
curl -fsSL https://hausfold.co/haus.sh | bash

# or answer that in the URL, and skip the question
curl -fsSL https://hausfold.co/hacker.sh   | bash   # the full desktop
curl -fsSL https://hausfold.co/everyday.sh | bash   # if you don't write code
curl -fsSL https://hausfold.co/minimal.sh  | bash   # just the themed shell

# same answer as a flag
curl -fsSL https://hausfold.co/haus.sh | bash -s -- --desktop=minimal

# read it first, or pin an exact release and diff it against GitHub
curl -fsSL https://hausfold.co/haus.sh | less
curl -fsSL 'https://hausfold.co/haus.sh?ref=v2026.07.19' | less
```

That installs Nix if you don't have it, asks a few questions, and writes your
config. Piped or not, it reaches your terminal and interviews you. It does
**not** change your Mac on its own: it writes files, prints the one command that
activates them, and offers to run that for you, so you can stop in between and
read what it wrote.

Every desktop is a set of values for the same options, so anything one chose
your own file overrides in a line. Changing your mind is that line, not a
reinstall.

The URL proxies
[`bootstrap.sh`](https://github.com/hausfold/haus/blob/main/bootstrap.sh) from
the public repo. A desktop's URL serves that file with two lines added at the
top naming the desktop, so `haus.sh` is the one to diff. You get the latest
release by default, tags are dated, and a **release tag is the only thing
`?ref=` accepts**: anything else is refused rather than fetched, so a link
carrying someone else's commit can't serve you a script off this domain.

## Before you start

- A **Mac on Apple Silicon**, running a recent macOS. Intel isn't supported.
- **Xcode Command Line Tools.** The installer prompts for them if they're
  missing, then asks you to re-run.
- **No Nix yet, or [Determinate Nix](https://docs.determinate.systems/)**, which
  the installer lays down for you. Any other Nix at `/nix` stops the install and
  is left where it is.
- **10–15 minutes** and a few GB of download for the first build.

## What it does

<Steps>

<Step>
**Takes a rewind point.** A Time Machine local snapshot, before anything
mutates. If Time Machine is off it warns and carries on.
</Step>

<Step>
**Asks its questions.** Your git name and email, a desktop (hacker / everyday /
minimal / custom), an accent colour, a wallpaper, and an editor. haus installs
the one you name, Zed, VS Code, Cursor, helix, neovim, vim or nano, or "other"
for a command of your own that haus points at and does not install. The three
apps arrive as casks, adopting a copy already on your Mac rather than laying
down a second one. Then whether to keep your current Dock, keyboard and Finder
settings, and whether to adopt the Homebrew casks you already have.
</Step>

<Step>
**Shows a read-only report.** Which dotfiles get backed up, which macOS settings
change, which casks it found.

<Callout type="warn" title="Dotfiles that would stop the first switch">
The report names any file that would **stop** the switch rather than be backed
up: a dotfile that is a *symlink* (a dotfiles repo, `stow`, `chezmoi`), or one
whose `<file>.backup` name is taken. Home Manager moves regular files aside and
refuses links on purpose, because silently deleting a link into your dotfiles
repo is the worse failure.
Clear each one it lists, or tell haus to skip that file
(`home.file.".profile".enable = false;`), before the build.
</Callout>
</Step>

<Step>
**Writes `~/.config/nix/` and commits it to git.** A small flake importing haus,
plus a host file of your answers. **No app you installed is ever removed.**
</Step>

<Step>
**Offers to activate.** Nothing is live yet. The last thing it asks, wherever
there's a terminal to ask on, is whether to run the two commands below, then
`haus doctor`. Unattended it stops here and prints them.
</Step>

</Steps>

## Build and switch

```sh
cd ~/.config/nix
nix build .#darwinConfigurations.$(scutil --get LocalHostName).system \
  && sudo ./result/sw/bin/darwin-rebuild switch --flake .
```

The build runs first, so a failed build never touches your system. **The first
run is slow; it's downloading the world.** When it lands, everything arrives at
once: apps install, the bar and tiling start, your terminal is themed, `haus`
joins your `PATH`. After that it's `haus rebuild`.

## If you regret it

| To undo | Use |
|---|---|
| The macOS settings | the Time Machine snapshot the installer took |
| Everything haus did | `haus rollback` (atomic, previous generation) |
| Apps | yours. haus never uninstalls one you added |
| All of it | [Leaving](/docs/haus/leaving), every exit in turn, smallest first |

## Unattended installs

Every question has an environment variable, so the whole thing can run without a
prompt:

```sh
HAUS_NONINTERACTIVE=1 \
HAUS_GIT_NAME="Ada Lovelace" \
HAUS_GIT_EMAIL="ada@example.com" \
HAUS_ACCENT="mauve" \
bash -c "$(curl -fsSL https://hausfold.co/haus.sh)"
```

| Variable | Effect |
|---|---|
| `HAUS_NONINTERACTIVE=1` | Take the defaults, Determinate's own confirmation included, so a run with no terminal at all (ssh, CI, a provisioning wrapper) gets through |
| `HAUS_DRY_RUN=1` | Print the config it would write, write nothing. Still asks the questions if you have a terminal; pair it with `--defaults` for a silent run |
| `HAUS_DESKTOP` | `hacker`, `everyday`, `minimal` or `blank`, or `--desktop=<name>` on the command line. Skips that question even interactively, which is what a desktop's URL does |
| `HAUS_ROOMS` | Rooms to turn on one by one, instead of a desktop's selection |
| `HAUS_GIT_NAME` / `HAUS_GIT_EMAIL` | Your git identity, which the host file records |
| `HAUS_ACCENT` / `HAUS_WALLPAPER` / `HAUS_EDITOR` | The look, and the editor (`zed`, `vscode`, `cursor`, `helix`, `neovim`, `vim`, `nano`) |
| `HAUS_GUI_EDITOR` | Point `$EDITOR` at a command haus does not install (e.g. `"subl -w"`); the editor above still installs as fallback |
| `HAUS_KEEP` | macOS settings to leave alone (`dock,keyboard,finder`) |
| `HAUS_DIR` | Scaffold somewhere other than `~/.config/nix` |
| `HAUS_FROM` | Restore an existing config instead of scaffolding |
| `HAUS_PRESET=full` | The pre-desktops spelling for `hacker`, still honoured |

Reach for these if you hand the install to a coding agent: the questions are a
terminal UI, and a tool driving one blind is how someone else's git identity
ends up in your config. An agent can do everything up to the build. The two
`sudo` steps are yours.
