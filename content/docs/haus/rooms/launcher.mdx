The Launcher room installs **[pounce](/docs/pounce)**, a native command palette
where every command is a shell script in a folder. Hit **⌘Space**, fuzzy-type,
hit **Return**: apps, your own commands, clipboard history, an emoji grid and
inline answers, all in one list.

Pounce is free, MIT and installs standalone from Homebrew without any of this.
What the room adds is the wiring: the daemon as a login item, ⌘Space actually
free, and the one macOS permission surviving a rebuild.

## Enable it

```nix
haus.launcher.enable = true;
haus.keys.palette = "cmd-space";   # or alt-space, ctrl-space, "none"
```

```sh
haus rebuild
```

Only `cmd-space` displaces Spotlight; moving the palette elsewhere is how you
keep both. haus frees ⌘Space from Spotlight so the palette can own it, which is the
step a standalone install has to do by hand.

## Configure it

`config.json` is **generated** from `haus.launcher.*`, so `pounce config init`
refuses inside haus; the next rebuild would put the generated file straight
back. Change it in your host file instead, and the rebuild bounces the daemon
for you when one of the startup-only keys moves.

```nix
haus.launcher.windowSwitcher = true;          # ⌘Tab by window; defaults on here
haus.launcher.autoQuit.enable = false;        # quit an app when its last window closes
haus.launcher.items."mode:emoji".hotkey = null;   # leave Fn/Globe native
```

`haus.ui.scale` writes the palette's `scale` for you, and your `haus.theme.flavor` /
`haus.theme.contrast` reach it as a palette file, so the palette matches the
rest of the house without a second theme setting.

### Rows that are listed on some pages only

haus scopes three rows this way: **New Agent Lane** (⌘⏎), **New Shell Window**
(⌘N) and its `⇧` twin. All three act on **the page you are standing on**, and
fall back to the window you were looking at when that page names no repo — so
from a browser they have nothing to read either way: the lane finds no repo and
refuses out loud, the shell opens in `$HOME`. They are listed on the terminal
pages only, `T` and every `T/<repo>` lane page:

```nix
# hand it back everywhere:
haus.launcher.items."cmd:lane-here".workspaces = [ ];

# or follow the app instead of the page, which needs BOTH lines: the two
# predicates are ANDed, so adding bundleIds on its own only narrows the row
# further (on T, and with Ghostty in front).
haus.launcher.items."cmd:lane-here".workspaces = [ ];
haus.launcher.items."cmd:lane-here".bundleIds = [ "com.mitchellh.ghostty" ];
```

**Spawn Agent** is untouched and stays everywhere, because it asks which repo
rather than inheriting one. That makes it the row to reach for from a browser,
where the lane chord cannot go. **New Terminal Window** (⌘T) stays everywhere
too, for the opposite reason: it inherits nothing at all, so there is no page it
needs to be on to work.

Both keys work on any item, and they scope the **row** and never a `hotkey` on
the same item, so ⌘⏎ and ⌘N keep working wherever Ghostty is frontmost. What
each one matches, and what `pounce doctor` reports about a row you cannot find,
is [the palette's own side](/docs/pounce/config#rows-that-only-exist-where-they-work).

The room's half: haus writes the scoping only where the
[Windows](/docs/haus/rooms/windows) room is on, since that room is what gives
Ghostty a page to be on and what runs the workspace hook the palette reads to
know where you are. Without a tiler no scoping is written at all and those three
rows stay everywhere.

A fourth row can be absent for a different reason. **Pages** isn't scoped to a
workspace, its list is every workspace's pages at once, but it hides itself
while no page exists anywhere, through a
[`whenFile`](/docs/pounce/writing-commands#a-row-that-hides-when-there-is-nothing-to-act-on)
in the command script rather than through `haus.launcher.items`. The file it
watches is written by the Windows room's workspace hook, and a file nothing ever
writes reads as a yes, so on a machine with no tiler the row stays, where, like
every page chord, it has nothing to work with. `pounce doctor` says which of the
two is happening.

### The Fn/Globe key

haus binds the emoji picker to Fn, and macOS wants that key too, so
`haus.launcher.fnKey` settles the argument: `"tap"` (the default) shares the key
and may lose the race, `"remap"` turns Fn into F19 and owns it outright at the
cost of Fn's other jobs: no Fn+arrows, no Fn+Delete. [What each mode
does](/docs/pounce/config#the-fnglobe-key-fnkey) is the palette's own side.

The room's half: here the remap is **declared** rather than installed by the
daemon, so a rebuild can't drop it and Fn stays remapped (and inert) while
the palette is stopped. Or hand the key back with
`haus.launcher.items."mode:emoji".hotkey = null`.

### Copy Text from Screen

**⌘⇧2** — beside macOS's own ⌘⇧3/4/5 capture family, but the crop's **text** is
the product: the same drag-an-area crosshair, then the text inside it lands on
the clipboard. Recognition is Apple's Vision framework, entirely offline, and
the image is deleted either way — nothing is ever saved. Esc during the drag
cancels quietly; a capture with nothing legible in it says so as a
notification instead of leaving you to paste and find out.

The first capture makes macOS ask for **Screen Recording** for Pounce — one
click. If that dialog got dismissed, `haus permissions` has the card: without
the grant, captures quietly come back wallpaper-only and every crop reads as
"No text found".

It is a palette row like any other (`⌘Space` → "copy text"), so the key follows
the item rules:

```nix
haus.launcher.items."cmd:copy-text".hotkey = "cmd+shift+6";  # move it
haus.launcher.items."cmd:copy-text".hotkey = null;           # palette row only
```

<Callout title="Keeping the Accessibility grant">
```nix
haus.launcher.signingIdentity = "Apple Development: you@example.com (XXXXXXXXXX)";
```

A plain Nix rebuild is ad-hoc signed, and macOS ties an Accessibility grant to
a signature, so without this you re-approve the dialog after every rebuild.
Set it and the room re-signs a stable copy of the app with your identity, and
the grant persists.

It is **host-only**: it names a certificate on one machine, so a shared desktop
may not set it.
</Callout>

## Works with

- **[Apps](/docs/haus/rooms/apps)**: **Install App** writes a roster entry and
  rebuilds.
- **[AI](/docs/haus/rooms/ai)**: **Spawn Agent** creates a named worktree and
  opens a session in it.
- **[Focus](/docs/haus/rooms/focus)**: the quiet switch is a command here too,
  and every scene you declare gets a **Scene: &lt;name&gt;** row of its own.
- **[Development](/docs/haus/rooms/development)**: **Lanes** jumps to an agent
  lane or searches what the agents are saying, **New Agent Lane** is ⌘⏎ and
  **New Shell Window** is ⌘N (both listed on the terminal pages, as above).
  **New Terminal Window** is ⌘T — the neutral one, home directory and no page —
  and is listed everywhere.
- **[Windows](/docs/haus/rooms/windows)**: the opt-in `⌘Tab` window switcher,
  which groups its rows by AeroSpace workspace.

Each command appears only when its room is on.

## Remove it

```nix
haus.launcher.enable = false;
```

<Callout type="warn" title="⌘Space doesn't go back on its own">
haus disables Spotlight's shortcut with a one-way write, and nothing re-enables
it. Put it back yourself in System Settings ▸ Keyboard ▸ Keyboard Shortcuts.
</Callout>
