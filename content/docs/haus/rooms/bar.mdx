**The bar** replaces the macOS menu bar with a scriptable status bar, painted in
your palette and wired to your tiling. While it's on, the native menu bar is
hidden; the bar is the one place to glance.

## Enable it

```nix
haus.bar.enable = true;
```

## What's on it

**Far left: the house.** Where macOS puts the Apple menu. It opens a menu,
and its colour tells you whether the machine is fine. See
[the logo pill](#the-logo-pill).

**Left: your workspaces.** One pill each, showing the workspace's id or its
icon, with the focused one highlighted and the front app's title alongside.
Switch workspaces and the highlight follows; tap the Caps-Lock leader and the
whole left side flips into launcher letters.

**Right: the status cluster.** Clock, battery, Wi-Fi, weather and media, all
on by default and each one hideable. More readouts are available and off by
default; see [toggling pills](#toggling-pills).

## Dropdowns

Several pills open a dropdown on click: weather, the calendar's timeline, the
coffee pill's durations, the cpu and memory breakdowns, media. They behave like
every other menu on the Mac: click elsewhere and it closes, click the pill again
and it closes, open a second one and the first closes.

## The logo pill

### It opens a menu

| Gesture | What you get |
|---|---|
| **Click** | System Settings, Activity Monitor, Lock Screen, your config, Rebuild System |
| **⌘ click** | `haus rebuild`, in a floating terminal |
| **Right click** | The full palette, the same thing ⌘Space opens |

Every row of that menu *is* a palette command, so anything you can click you
can also type. `haus.bar.logo.gestures = false` turns all three off, so the
pill is plainly not a button rather than a button that does nothing.

### It tells you the machine is fine

| Colour | Meaning |
|---|---|
| Your accent | Everything is running |
| Yellow | A newer version is available: `haus update` |
| Red | Something is enabled but **not running** |

Red is the one worth having. A wedged background agent is otherwise invisible:
tiling stops but leaves every window where it was, and a dead bar keeps the
last frame it drew on screen. The check is local, free, and runs every five
minutes.

The **yellow** half asks GitHub whether a new version exists (the only thing
this pill does that leaves your machine), so it's **off by default**. Turn it
on with `haus.bar.logo.updateCheck = true`.

<Callout title="Hover it">
Resting the pointer on the pill sweeps it through the six hausfold accents. It
only runs at the pill's resting colour: a pill that has gone yellow or red has
something to say and doesn't also get a rainbow. `haus.bar.logo.sweep = false`
if you'd rather it sat still.
</Callout>

### Changing the glyph

```nix
haus.bar.logo.icon = "⌂";
haus.bar.logo.size = 25;    # ⌂ is drawn thin; it needs the extra points
haus.bar.logo.color = "teal";
```

Left alone, the colour follows `haus.theme.accent`. The default is a solid
Nerd Font house at 20pt. Whatever you pick has to hold up in a 28pt pill, which rules out more than
you'd expect; the options reference lists six that work. You can't point it at
an image file: a picture couldn't follow your accent or show any of the states
above.

## The media pill

It reads the same system-wide session Control Center does, so it follows a
browser tab as readily as Apple Music, and it hides itself entirely when
nothing is playing.

| Gesture | What it does |
|---|---|
| Left click | The dropdown |
| Right click | Play / pause |
| ⌥ click | Next track |
| ⇧ click | Previous track |
| **⌘ click** | **Bring the app making the sound forward** |
| Scroll | Seek ±10s |
| Hover | Sweep a long title, once |

That ⌘ click is the one to remember: it's the answer to *something is making
noise and I can't find the tab*.

Two habits. A long title never scrolls on its own, only on hover, and a sweep
always finishes once started. And anything over twenty minutes counts **down**
(`-38m`) instead of scrolling a name you already know.

The dropdown carries cover art, title, artist, album, and a position slider you
can click to scrub.

```nix
haus.bar.media.collapse = true;   # glyph only until you hover, good on a notched Mac
haus.bar.media.width = 16;        # characters of title before it sweeps. 25 by default.
```

`width` is a maximum, not a fixed size: a short title still draws a short pill.
`haus.bar.media.marquee = false` stops the sweeping entirely — on the pill and in
the dropdown — and clips instead;
[`haus.appearance.reduceMotion`](/docs/haus/rooms/appearance#motion) sets that,
`haus.bar.calendar.marquee` and `haus.bar.logo.sweep` together.

## Toggling pills

Every right-side pill is one boolean. The five core pills (`clock`, `weather`,
`media`, `battery`, `wifi`) default **on**; everything else defaults off. Set
only what you want to change:

```nix
haus.bar.items = {
  weather = false;      # drop a core pill
  cpu = true;           # add an off-by-default readout
  caffeinate = true;
};
```

A pill set `false` is never created; its update script doesn't even run.

### The extra readouts

| Pill | What it is |
|---|---|
| `cpu` | Load, drawn as a graph of the last two minutes. Hover splits user vs system; click lists what's responsible, per app; right-click opens Activity Monitor. |
| `memory` | Memory in use, as a graph. Coloured by the kernel's own pressure level, not the percentage: 60% in use is a Mac working correctly. |
| `volume` | Output volume and mute state. |
| `calendar` | Your next meeting and one gesture to join it. Reads `in 12m · Design review`; the whole pill fills five minutes either side of the start. **Right-click joins** the conferencing link; left-click opens the day as a timeline. |
| `caffeinate` | A coffee pill: click for 1, 2, 4, 8 hours or until stopped; right-click stops. Survives a bar reload. |
| `page` | Which repo page you're on: the `T/<repo>` workspace a [lane](/docs/haus/rooms/development) tiles itself onto. It draws only on the terminal pages and stays silent everywhere else, because "which repo" has no answer on the page holding your notes. Click opens the **Pages** picker to go to one; ⇧/right-click opens the same list in move mode, throwing the focused window onto the page you pick and following it there. Needs `haus.windows.enable`. |
| `agents` | Tracks your [agent](/docs/haus/rooms/ai) lanes, and Claude Code desktop sessions too: red when one is waiting on you, click to jump to it. |
| `aiUsage` | How much of your AI usage you've spent, as a gauge. Click for every provider's windows and reset times. |
| `github` | What's waiting on you across GitHub, from sources you name in `haus.bar.github.sources`: a search filter, the `ci` board, or your own command. Two-tone: the **number** is how many, the **octocat** is how bad, taking the worst single row: red for a conflict or failed checks, amber for changes requested or a run still going. Click for the rows, each one a link; right-click refreshes. Needs the [Development room](/docs/haus/rooms/development)'s git, a `gh auth login` you've run, and either `haus.git.org` (which fills the sources with that owner's red default branches and open PRs) or your own `haus.bar.github.sources`. Turning the pill on with neither fails the build rather than drawing an empty pill. |
| `elgato` | Toggles an Elgato Key Light on your network. |
| `harvest` | Harvest time tracking. Reads credentials from a file you provide. |

The keep-awake engine is also a command, with or without the pill:

```sh
awake 3h
awake indefinitely
awake off
```

The **focus** (Do Not Disturb) pill is separate: whether it exists is
`haus.focus.enable`, not `haus.bar.items`. Where it goes is still a bar
setting, which is why it can appear in `haus.bar.bottom.items` below.

## Writing your own pill

`haus.bar.items` covers the pills haus ships. A pill it doesn't ship is
`haus.bar.widgets` — one script, run on a timer, whose output is the label:

```nix
haus.bar.widgets.backup = {
  command = "/etc/haus/backup-status.sh";
  interval = 300;
  icon = "󰁯";
};
```

That's the whole requirement. One line on stdout is the label; print nothing and
the pill hides for that tick, which is how a widget says "no news" without
drawing an empty box. `placement = "bottom-left"` puts it on the second bar
instead.

Every bundled pill is declared here too, so you can retune one by name without
turning it off and rebuilding it yourself:

```nix
haus.bar.widgets.weather.interval = 1800;   # ask half as often
haus.bar.widgets.cpu.placement = "bottom-right";
```

`haus.bar.items.<name>` is sugar for `haus.bar.widgets.<name>.enable`, and
`haus.bar.bottom.items.<name>` for its `placement` — the same settings under
shorter names, so both spellings work and you can keep whichever reads better.

Some things a widget can't do, each refused at build rather than silently: you
can't set `command` on a bundled pill (its dropdown, click gestures and colour
rules are written against haus's own script, so replacing half of it would leave
you with something neither of us can reason about — write your own under a new
name and switch that one off), you can't place a pill on the bottom bar without
`haus.bar.bottom.enable`, and the name has to be a plain word the bar can
address: letters, digits, `_` and `-`, and not one the bar already uses.

<Callout type="info" title="Say what it will ask for">
`permissions = [ "full-disk-access" ]` declares what macOS will prompt your
widget for. Nothing requests it and nothing waits on it — it's there so a
widget you got from someone else can be read for what it reaches for before you
switch it on, and so a tool can answer "which pill here is going to prompt me"
without a second hand-kept list.
</Callout>

One rule if your script talks back to the bar: source
`~/.config/sketchybar/bar.sh` and use `$SB`, never a bare `sketchybar`. A pill
moved to the bottom bar belongs to a second instance, and a bare `sketchybar`
always means the top one — same syntax, no error, and a pill that just stops
updating.

<Callout type="info" title="Secrets stay out of Nix">
The bar never bakes a token into the build. The Harvest pill sources your own
credentials file at runtime; `aiUsage` reads your existing Codex login the same
way. Keep those files out of git.
</Callout>

## A second bar along the bottom

If you want more room, or you'd rather keep the readouts off the menu bar
entirely, the room can draw a second bar along the bottom of the screen at the
same time:

```nix
haus.bar.bottom = {
  enable = true;
  items = { weather = "left"; media = "center"; focus = "right"; };
};
```

A pill named here **moves**: it's drawn on the bottom bar and not the top one,
whatever `haus.bar.items` says. Never two copies racing each other.

The value is where it goes: `"left"`, `"center"` or `"right"`; `true` means
`"right"`. The menu bar only has one usable group (its left is the workspaces,
its middle is under the notch on a MacBook), so the bottom strip is where all
three are yours.

Three things before you turn it on:

- **macOS reserves nothing at the bottom of the screen.** Tiling carves the
  room out instead, so with tiling off, windows will run underneath it.
- **The Dock shares that edge.** Move it to a side, or hide it.
- **Don't put both bars on the same edge.** `haus.bar.position = "bottom"`
  plus a second bar is two bars in one place; you'll get a warning on rebuild.

## Turning it off

```nix
haus.bar.enable = false;
```

The native menu bar comes back, and the bottom bar goes with it. Tiling and
everything else are unaffected.

## Works with

Every pill that isn't the bar's own comes from another room, and appears only
when that room is on:

- **[Windows](/docs/haus/rooms/windows)**: the workspace pills and the leader's
  letter hints;
- **[Focus](/docs/haus/rooms/focus)**: the quiet switch's pill;
- **[AI](/docs/haus/rooms/ai)**: the agents readout, red when a session is
  waiting on you;
- **[Launcher](/docs/haus/rooms/launcher)**: what a click on the logo pill can
  reach.

A missing room removes its pill and nothing else.
