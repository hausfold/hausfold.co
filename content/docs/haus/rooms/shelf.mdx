Flick a drag up to the notch and a shelf drops down to catch it:
[perch](/docs/perch), wired up here.

## Enable it

```nix
haus.shelf.enable = true;
```

```sh
haus rebuild
```

Off by default. On, Perch.app is copied to `/Applications`, kept current, and
`perch` goes onto your PATH:

```sh
perch add report.pdf shot.png     # and list, rm, doctor
```

The room grants nothing. It switches **Desktop & Dock ▸ "Drag windows to top of
screen to enter Mission Control"** off without asking: the shelf cannot work
with it on.

## Colour

```nix
haus.shelf.followSystemAppearance = true;
```

On, the shelf follows macOS Light/Dark at your `haus.theme.contrast`, no
rebuild, no relaunch, rather than your
[`haus.theme.flavor`](/docs/haus/rooms/appearance) like every other themed tool.

## Screenshots

```nix
haus.shelf.watchScreenshots = true;  # the default wherever the shelf is on
```

Screenshots reach the shelf on their own through a watched folder; this clears
macOS out of the way. The floating thumbnail goes off
(`haus.screenshots.thumbnail`, at `mkDefault`, so naming it in your host puts it
back): macOS *holds* the capture for about five seconds before writing the file,
so a watched folder catches it that late. And where this machine owns
`haus.screenshots.location`, the folder goes into `~/.config/perch/config.json`,
perch's fallback for finding it when macOS is silent.

## Remove it

```nix
haus.shelf.enable = false;
```

haus stops installing and updating perch. `/Applications/Perch.app` stays until
you delete it, and the Mission Control setting keeps the value haus wrote, so
flip that back by hand. While the room is on, every rebuild ends with the shelf
running: one you quit comes back.
