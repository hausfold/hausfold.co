**Security** is the auth room: what you prove yourself to, what you are excused
from proving, and where this Mac's secrets come from.

## Enable it

```nix
haus.security.touchId.enable = true;
haus.security.touchId.passwordlessRebuild = true;
```

Off in the bare layer; hacker, everyday and minimal all turn both on.

`enable` puts [`pam_reattach`](https://github.com/fabianishere/pam_reattach) in
front of `pam_tid`, without which `sudo` inside tmux or the `zmx` session every
haus terminal window runs in beachballs instead of prompting. Type `sudo -v` and
the dialog floats over the multiplexer; cancel it and the typed password still
works.

`passwordlessRebuild` writes `/etc/sudoers.d/darwin-rebuild`:

```
<you> ALL=(ALL) NOPASSWD: /run/current-system/sw/bin/darwin-rebuild
<you> ALL=(ALL) NOPASSWD: /run/current-system/sw/bin/haus-activate
```

so `haus rebuild` and `haus rollback` never stop for a fingerprint you already
gave. It is a real root grant, anything you can build you can activate
unprompted, so turn it off on a machine you don't administer alone. It names the
stable path because sudo 1.9.17 (macOS 26.6) stopped
dereferencing symlinks before matching sudoers, so a `/nix/store/…` rule matches
only the literal path.

Key material never enters Nix: YubiKey, GPG and `pinentry` are `gpg-agent`'s at
runtime, and `haus.git.signingKey` wires up commit signing over in [the
Development room](/docs/haus/rooms/development).

## Secrets your rooms need

A room needing a value haus cannot invent declares it, so **the room asks, not
you**, and haus asks once for all of them:

```bash
haus-secret --list     # what this Mac is asking for, and where to get each one
haus-secret --check    # enter what's missing
haus-secret --status   # which ones have a value (it prints no values)
```

Values land wherever `haus.secrets.provider` names: `"keyring"`, this Mac's
login keychain, by default, or `"onepassword"`, `"bws"`, `"gcsm"`, `"vault"` and
the rest secretspec takes. Never your config, a dotfile or the store. `haus
doctor` and `haus permissions` name the empty ones; turn a room off and its
secret stops being asked for.

<Callout title="Two lists of secrets, and they are not the same one">
A *project* declares its own in a `secretspec.toml` beside its code, which
[secretspec](https://secretspec.dev) finds by itself under
`secretspec run -- npm start`. The list above is the **machine's**, read only by
`haus-secret`, in a separate namespace: the same name in both is two values.
Point `haus.secrets.project` at a project you already use to share one.
`haus.secrets.provider` and `.project` are both host-only.
</Callout>

## The rest of the room

Unset by default, so a fresh Mac keeps macOS's own answer:

```nix
haus.lock.requirePassword     = true;   # and .requirePasswordDelay
haus.security.firewall.enable = true;   # the built-in one, off on a fresh Mac
haus.security.guestAccount    = false;  # the passwordless Guest login
haus.lock.login.showNameField = true;   # a name to type, not faces to shoulder-surf
haus.lock.login.message       = "If found, please call +1 555 0100.";
haus.lock.login.hideShutDown  = true;   # and .hideRestart, .hideSleep
```

**`guestAccount` is the one worth doing today.** Fresh Macs ship with Guest
**on**, so a machine nobody configured hands whoever is holding it a browser,
your network and any file share you are connected to, no password. The firewall
is worth it on a laptop that joins networks you don't own. `message` reaches
somebody who *cannot* log in, which is what makes "how to reach me" the thing to
put there.

`haus.security.touchId.enable = false` puts the password prompt back
everywhere. The keys above stop being written but keep whatever value they last
had: unsetting an option stops managing a macOS setting rather than restoring
the one before it.

<Callout title="These land at your next login">
`guestAccount` and every `haus.lock.login.*` key write to
`com.apple.loginwindow`, which macOS reads once when your session is created:
the only "restart" would be logging you out. The rebuild writes them, your next
login shows them, nothing is half-applied between. `haus plan` names them before
you rebuild.
</Callout>
