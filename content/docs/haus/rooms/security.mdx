**Security** is the small auth room: it turns on **Touch ID for `sudo`**, and
(the part stock Touch-ID-for-sudo gets wrong) makes that work **inside a
terminal multiplexer** like tmux or `zmx` (which every haus terminal window
runs inside), where it would otherwise silently
fail.

## Enable it

```nix
haus.security.touchId.enable = true;
haus.security.touchId.passwordlessRebuild = true;
```

## What it turns on

```nix
security.pam.services.sudo_local.touchIdAuth = true;   # fingerprint for sudo
security.pam.services.sudo_local.reattach   = true;    # make it work in tmux/zmx
```

`reattach` pulls in [`pam_reattach`](https://github.com/fabianishere/pam_reattach),
which reattaches the sudo process to your GUI login session. Without it,
`sudo` inside a multiplexer detaches from Aqua and the Touch ID prompt just
beachballs. Cancel the prompt and it falls back to a typed password.

The room also installs `/etc/sudoers.d/darwin-rebuild`, exempting activation
from authentication entirely:

```
<you> ALL=(ALL) NOPASSWD: /run/current-system/sw/bin/darwin-rebuild
<you> ALL=(ALL) NOPASSWD: /run/current-system/sw/bin/haus-activate
```

Activating a build is the one privileged thing this desktop does constantly,
and a prompt per rebuild buys nothing: you already authenticated to *build*
it. `darwin-rebuild` is the classic route (and the only one for `haus
rollback`); `haus-activate` is the faster path `haus rebuild` and `bench try
switch` take, building as you and handing the result to root without a
second evaluation. Neither is a wider grant than `darwin-rebuild switch
--flake <anything>` already was; `haus.security.touchId.passwordlessRebuild = false`
drops both.

<Callout type="warn" title="Why the stable path, not the store path">
macOS 26.6 shipped sudo 1.9.17, which stopped dereferencing a command's
symlink before matching sudoers: a rule against a `/nix/store/…` path only
matches if you type that literal path, which nobody does. Matching
`/run/current-system/sw/bin/darwin-rebuild` is what survives a rebuild.
</Callout>

<Callout title="Yes, it works inside a session">
Type `sudo -v` in a terminal window and the Touch ID dialog floats up right over
the multiplexer. Touch the sensor, no password typed. (`darwin-rebuild` is
the happy exception; it doesn't even ask.)
</Callout>

## What it does *not* do

The room stays out of key management. **YubiKey and GPG** live outside Nix
entirely: key material, smartcard setup, and `pinentry` are handled by
`gpg-agent` + `pinentry-mac` at runtime, keeping secrets off the Nix store.
Commit signing itself is wired up in [the Development room](/docs/haus/rooms/development)
from `haus.git.signingKey`; security only handles `sudo` authentication.

## Two switches

```nix
haus.security.touchId.enable = true;              # Touch ID for sudo, reattach and all
haus.security.touchId.passwordlessRebuild = true; # activation never authenticates
```

Both default on. Turn `passwordlessRebuild` off on a machine you don't
administer alone, and activation goes back to asking. Turn `enable` off and
macOS's stock password prompt comes back everywhere.

## The rest of the room

Three more surfaces, each unset by default so a fresh Mac keeps macOS's own
answer until you say otherwise:

```nix
haus.lock.requirePassword = true;        # and .requirePasswordDelay
haus.security.firewall.enable = true;    # the built-in application firewall
haus.secrets.provider = "keychain";      # where secret values come from
```

The firewall is off on a fresh Mac; it is the setting to turn on for a laptop
that joins networks you don't own. Secrets themselves never live in your
config; haus declares which exist and fetches them at runtime.

## The login window

Everything above is about a session you're already in. These are about the
screen before it, and they are the settings most people have never touched,
because macOS asks nobody about them:

```nix
haus.security.guestAccount    = false;   # the passwordless Guest login
haus.lock.login.showNameField = true;    # type a username, don't pick a face
haus.lock.login.message       = "If found, please call +1 555 0100.";
haus.lock.login.hideShutDown  = true;    # and .hideRestart, .hideSleep
```

**`guestAccount` is the one worth doing today.** Fresh Macs ship with Guest
**on**, so a machine you never configured lets whoever is holding it reach a
browser, your network and any file share you're connected to, without a
password. It's the only genuine security boundary in this group; the rest are
preferences.

`showNameField` is the shoulder-surfing one: the default list of user pictures
puts half a credential on screen for anyone walking past. `message` is shown to
somebody who *cannot* log in, which makes "how to reach me" the one genuinely
useful thing to put there.

<Callout title="These land at your next login">
  Every setting in this section writes to `com.apple.loginwindow`, which macOS
  reads once when your session is created. There is no process to restart that
  would make it read again: the one that owns the domain is the one that owns
  your session, so the "restart" would be logging you out. **The write happens
  during the rebuild and the effect appears at your next login.** Nothing is
  half-applied in between.

  You don't have to remember which settings those are: `haus plan` says so
  before the rebuild, the rebuild says so as it runs, and each option's own
  reference entry says so.
</Callout>

## Works with

- **[Development](/docs/haus/rooms/development)**: commit signing is configured
  there; this room is what stops `sudo` asking for a password.
- **[AI](/docs/haus/rooms/ai)**: `passwordlessRebuild` is what lets an agent
  run `haus rebuild` end to end without a prompt it can't answer.

## Remove it

```nix
haus.security.touchId.enable = false;
```

`sudo` goes back to the password prompt. The firewall and lock settings stop
being written but keep whatever value they last had: unsetting an option stops
managing a macOS setting rather than restoring the one before it.

`haus.secrets.provider` is host-only: where a machine keeps its secrets is a
fact about that machine.
